# Amazon Clone App

A full-stack clone of Amazon's storefront and checkout flow, built with React and Firebase. Live at **[clone-project-1c2c3.web.app](https://clone-project-1c2c3.web.app)**.

## Overview

This project recreates the core shopping experience on Amazon's homepage: browsing products, adding items to a basket, authenticating with email/password, and reviewing a basket subtotal at checkout. It's built as a single-page application with client-side routing, global state management, and a Firebase backend for authentication.

## Features

- **Product browsing** — a responsive product grid with images, pricing, and star ratings
- **Basket management** — add/remove items with basket state shared across the whole app
- **Authentication** — email/password sign-in and sign-out via Firebase Auth
- **Checkout page** — basket review with a live-calculated, currency-formatted subtotal
- **Client-side routing** — home, login, and checkout as distinct routes without full page reloads

## Tech Stack

- **React 19** — functional components with hooks throughout
- **React Router v7** — client-side routing
- **Context API + `useReducer`** — global state (basket, logged-in user) via a single reducer, avoiding prop drilling without pulling in an external state library
- **Firebase** — Authentication and Firestore (client SDK), Firebase Hosting for deployment
- **Material UI** — icon components
- **GitHub Actions** — CI/CD: every push to `main` builds and deploys to Firebase Hosting automatically, and every pull request gets its own preview deploy channel

## Engineering Highlights

This repo has gone through a real debugging and hardening pass, not just an initial build:

- **Root-caused and fixed a broken production build** — tracked a CI failure through several layers: a missing template literal breaking the lint gate, a component importing a file that didn't exist (silently dead code, since it was never routed), invalid JSX inside a third-party component's props, and a stale peer-dependency conflict (`npm ci`'s strict resolution vs. a legacy package's React version constraint) — resolved by reproducing the exact CI environment locally in a clean clone rather than guessing.
- **Fixed a misconfigured CI/CD pipeline** — the GitHub Actions workflows (auto-generated by the Firebase CLI) assumed the app lived at the repo root; corrected the working directory, added the missing dependency-install step, and pointed the deploy action at the right `firebase.json`.
- **Caught and fixed a Firebase Hosting misconfiguration** — hosting was pointed at a stale placeholder directory instead of the actual production build output.
- **Verified fixes against ground truth, not assumptions** — used the GitHub Actions REST API directly to confirm workflow run status and pull real job logs, after noticing that a JS-rendered dashboard page could return a plausible-looking but fabricated summary.
- **Cleaned up dead weight** — removed unused files, orphaned CSS rules, and files that were accidentally committed (build caches, boilerplate never wired into the app), keeping the repo lean and its `.gitignore` accurate.

## Getting Started

```bash
cd amazon-clone
npm install --legacy-peer-deps
npm start          # runs the dev server at localhost:3000
npm run build      # production build
```

Firebase config lives in `amazon-clone/src/firebase.js`; hosting config is in `amazon-clone/firebase.json`.
